# Диагностика

## OAuth успешен, модель не отвечает

- Проверь `hermes auth status openai-codex` и `hermes auth list openai-codex`.
- Проверь, что `model.provider` — `openai-codex`.
- Для Codex при `invalid_grant` или 401 проведи новый device-code login.
- Запусти безопасный one-shot без пользовательских данных.

## В терминале работает, gateway — нет

- Сравни Linux-пользователя интерактивной сессии и `User=` systemd-юнита.
- Сравни `HOME` и `HERMES_HOME` в unit с каталогом, где лежат OAuth-файлы.
- Проверь владельца и права `config.yaml`, `.env` и `auth.json`.
- Переустанови unit штатной командой Hermes после исправления окружения.

## Telegram молчит

- Проверь `getMe`, не раскрывая токен в выводе.
- Проверь числовой allowlist и `GATEWAY_ALLOW_ALL_USERS=false`.
- Найди фактическое имя unit через Hermes, затем просмотри последние строки журнала.
- Убедись, что одновременно не запущены user-unit и system-unit с одним токеном.

## После обновления изменился CLI или конфиг

- Снова прочитай `hermes --help`, help нужной подкоманды и текущую официальную документацию.
- Не возвращай старые поля конфигурации из скилла.
- Сверь резервную копию, миграционные сообщения и `hermes status --all`.

## Сервер недоступен после SSH-хардненинга

Используй консоль VPS-провайдера, исправь sshd/UFW и восстанови ключевой вход. Не включай пароль обратно через небезопасный публичный SSH; если временный пароль необходим для восстановления, ограничь окно и отключи его после проверки ключа.
