# OAuth через ChatGPT / Codex

Это единственный модельный OAuth-путь в данном скилле. Claude Code может выполнять команды развертывания, но его OAuth не подключается к Hermes.

## Вход

До запуска device-code flow попроси пользователя проверить настройку в ChatGPT:

1. Открыть настройки нужного ChatGPT workspace.
2. Перейти в **Permissions & roles**.
3. В разделе **Codex Local** или **Codex and Work Local** включить **Enable device code authentication for Codex CLI** («Включить авторизацию кода устройства для Codex»).

Расположение и доступность переключателя зависят от типа workspace и текущего интерфейса. Если пользователь не видит настройку или не может изменить ее, нужен владелец/администратор workspace. Не запускай OAuth повторно, пока настройка не включена.

Запусти под тем же пользователем, который будет запускать gateway:

```bash
hermes auth add openai-codex --type oauth
```

Hermes должен показать URL, одноразовый device code и начать ожидать подтверждения. Передай URL и одноразовый код только владельцу аккаунта в текущем приватном канале. Пользователь открывает URL на своем компьютере или телефоне, входит в нужный ChatGPT workspace и подтверждает доступ. SSH-туннель для device-code потока не нужен. Не помещай одноразовый код в публичный гайд, Notion или скриншот.

Не запускай параллельно второй OAuth-процесс. Сохраняй PTY-сессию активной до успеха или явного таймаута.

## Проверка

```bash
hermes auth status openai-codex
hermes auth list openai-codex
```

Затем запусти `hermes model`, выбери «ChatGPT or Codex Subscription» / `openai-codex`: успешный OAuth-вход не заменяет настройку провайдера. Явный выбор модели пользователем имеет приоритет. Иначе на новой установке принимай модель, предлагаемую установленным Hermes по умолчанию для `openai-codex` (Enter, если интерфейс предлагает так подтвердить выбор), без поиска конкретного семейства или версии. На существующей установке предварительно выясни настроенную модель и сохрани ее при выборе провайдера; не заменяй ее новым default без указания пользователя. Сохрани глобальный reasoning effort `high`, если пользователь явно не указал другое значение.

Проверь фактические значения провайдера, модели и reasoning effort в конфигурации и выполни отдельный одноразовый запрос из раздела 4 основного скилла. Не продолжай к Telegram, если OAuth или этот запрос не прошли. В итоговом отчете укажи фактически настроенный slug модели, а не ожидаемое имя семейства или версии.

Hermes хранит свои OAuth-данные в `~/.hermes/auth.json` и обновляет токены. Файл должен принадлежать runtime-пользователю и иметь закрытые права. Не копируй локальный `~/.codex/auth.json` на VPS: прямой device-code вход проще, не переносит весь кэш авторизации и снижает риск конфликта одноразовых refresh token.

Если обновление токена завершилось `invalid_grant`, 401 или сообщением о повторном входе, выполни новый `hermes auth add openai-codex --type oauth`. Не редактируй токены вручную.

Доступность планов и то, как стороннее использование Hermes учитывается в лимитах Codex, могут меняться. Не обещай конкретную квоту; проверяй фактический статус учетной записи и текущую документацию. При недоступности Codex OAuth остановись и объясни ограничение — не предлагай Claude OAuth или API-ключ автоматически.
