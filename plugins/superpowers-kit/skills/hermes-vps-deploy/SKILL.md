# Hermes на VPS через OAuth

Доведи развертывание до проверяемого результата: выбранная через OAuth модель отвечает, Telegram принимает сообщения только от разрешенного пользователя, gateway переживает перезагрузку сервера, а SSH остается доступен по проверенному ключу.

Скилл совместим с Codex и Claude Code как с инструментами развертывания и не зависит от конкретной версии Hermes. Провайдер модели в этом сценарии — только ChatGPT/Codex OAuth. Claude Code может выполнить раскатку, но его OAuth нельзя подключать к Hermes по этому скиллу. Не применяй команды и поля конфигурации по памяти, если установленная версия показывает другой интерфейс.

## Неподвижные правила

- Не проси API-ключ модели, не подключай Anthropic/Claude OAuth и не переключайся на другой провайдер как запасной путь без отдельного нового решения пользователя.
- OAuth всегда требует участия пользователя. Покажи ему URL и одноразовый device code, затем дождись завершения авторизации. Не проси присылать access token, refresh token, `auth.json` или содержимое хранилища Codex.
- Запускай OAuth, настройку модели и gateway от имени одного и того же runtime-пользователя. Иначе токены окажутся не в том домашнем каталоге.
- На новом VPS предпочитай отдельного непривилегированного пользователя `hermes`. Не запускай gateway от `root`, если пользователь явно не выбрал этот компромисс.
- Не отключай парольный SSH-вход, пока отдельная проверка входа по ключу не вернула `KEY_OK`.
- Не перезаписывай существующие `config.yaml`, `.env`, OAuth-хранилища или systemd-юниты без резервной копии и понимания текущего состояния.
- Не фиксируй номер версии Hermes, семейство или версионный slug модели. Узнавай возможности через установленный CLI. Явный выбор модели пользователем имеет приоритет; иначе на новой установке принимай модель, предлагаемую установленным Hermes по умолчанию для `openai-codex`, а на существующей сохраняй настроенную модель. Reasoning effort — `high`, если пользователь явно не указал другое.
- Не публикуй гайд, токены или результаты во внешних сервисах без отдельного поручения пользователя.

## Что собрать

До изменений нужны:

- адрес VPS и SSH-пользователь;
- рабочий способ SSH-входа: ключ либо временный пароль;
- подтверждение, что модель нужно подключить через ChatGPT/Codex OAuth;
- токен Telegram-бота;
- числовой Telegram user ID владельца;
- желаемая таймзона, если ее нужно изменить.

Если сервер уже существует, сначала выясни, установлен ли Hermes и какой пользователь запускает сервис. Для существующей установки сохраняй найденную runtime-идентичность, если она безопасна и пользователь не просил миграцию.

## 1. Предварительная проверка

Подключись по SSH и проверь без изменений:

```bash
id
. /etc/os-release && printf '%s %s\n' "$ID" "$VERSION_ID"
uname -m
free -h
df -h /
command -v hermes || true
systemctl list-unit-files 'hermes-gateway*' --no-legend || true
```

Поддерживаемая цель этого сценария — актуальный Ubuntu/Debian с systemd. Остановись и объясни отклонение, если ОС или init-система другие. Для обычного агента желательно не менее 2 ГБ RAM; 4 ГБ дает заметно больше запаса.

Если Hermes уже установлен, собери:

```bash
hermes --version
hermes status --all
hermes gateway status --system || hermes gateway status || true
hermes update --check
```

Вывод статуса считай потенциально чувствительным: не показывай пользователю токены и не включай секреты в отчет.

## 2. Установка или обновление

Для новой установки поставь только базовые системные зависимости, затем используй актуальный официальный установщик:

```bash
apt-get update
apt-get install -y ca-certificates curl git openssh-client ufw fail2ban
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --non-interactive --skip-setup
```

Не выполняй полный `apt upgrade` без отдельного согласования: он не нужен для установки Hermes и может затронуть несвязанные сервисы.

Для существующей установки сначала сделай точечную резервную копию конфигурации и OAuth-хранилищ с UTC timestamp и правами только владельца. Затем используй поддерживаемый текущим CLI путь обновления (`hermes update --backup`, если он доступен). Не подменяй обновление новой установкой вслепую.

После установки обязательно выполни:

```bash
hermes --version
hermes --help
hermes auth add --help
hermes model --help
hermes gateway install --help
```

Если синтаксис ниже не совпадает с help установленной версии, следуй текущему help и официальной документации, сохраняя смысл процедуры.

## 3. Runtime-пользователь

На свежей установке создай отдельного пользователя:

```bash
id -u hermes >/dev/null 2>&1 || useradd --create-home --shell /bin/bash hermes
install -d -m 700 -o hermes -g hermes /home/hermes/.hermes
```

Убедись, что установленный `hermes` доступен этому пользователю. Все дальнейшие команды авторизации и выбора модели выполняй как `hermes`, например через интерактивную сессию:

```bash
sudo -iu hermes
```

Не копируй секретные файлы из `/root/.hermes` в `/home/hermes/.hermes`. Проведи отдельную OAuth-авторизацию под правильным пользователем.

Если официальный установщик разместил код и managed venv в системном каталоге от `root`, проверь, что runtime-пользователь может читать файлы и проходить по всем каталогам установки. Некоторые Python-команды создают `__pycache__` с правами `700`, из-за чего plugin discovery у непривилегированного gateway завершается `PermissionError`. Исправляй это только внутри подтвержденного каталога установки Hermes (например, добавлением `a+rX`); не меняй права домашнего каталога, `.env` или OAuth-хранилища.

## 4. OAuth и выбор модели

Прочитай [references/oauth-codex.md](references/oauth-codex.md), попроси пользователя проверить, что в настройках ChatGPT workspace включена device-code авторизация для Codex CLI, и только затем выполни вход через ChatGPT/Codex. Не предлагай Anthropic/Claude OAuth.

После успешной авторизации запусти под runtime-пользователем:

```bash
hermes auth status openai-codex
hermes auth list openai-codex
hermes model
```

В `hermes model` выбери «ChatGPT or Codex Subscription» / `openai-codex`: успешный OAuth-вход не заменяет настройку провайдера. Если пользователь явно указал модель или effort, следуй его выбору. Иначе на новой установке принимай предлагаемую установленным Hermes модель по умолчанию для этого провайдера (Enter, если интерфейс предлагает так подтвердить выбор), без дополнительного поиска другого семейства или версии. На существующей установке предварительно выясни настроенную модель и сохрани ее при выборе провайдера; не заменяй ее новым default без указания пользователя.

После выбора сохрани reasoning effort `high` для всех новых сессий, если пользователь явно не указал другое значение (тогда сохрани его). Сначала проверь синтаксис установленного CLI; в актуальном интерфейсе для `high` используется:

```bash
hermes config set agent.reasoning_effort high
```

Если `config set` в установленной версии недоступен, сделай резервную копию `config.yaml` и аккуратно установи `agent.reasoning_effort: "high"` (либо явно указанное пользователем значение) через поддерживаемый текущей версией способ. Сессионной команды `/reasoning high` без `--global` недостаточно.

После настройки проверь фактические значения: провайдер — `openai-codex`, модель соответствует явному выбору пользователя либо предложенному default новой установки / сохраненной модели существующей установки, reasoning effort — `high` либо явно указанное пользователем значение. В отчете укажи фактически настроенный slug модели, прочитанный из конфигурации, без предположений о семействе или версии. Не переключайся молча на API-ключ или другого провайдера.

Проверь модель отдельным одноразовым запросом без инструментов и без секретных данных:

```bash
hermes chat --oneshot --query "Ответь одним словом: OK"
```

Не продолжай к Telegram, если OAuth или этот запрос не прошли.

## 5. Telegram

Создай или аккуратно обнови `.env` runtime-пользователя. Сохрани посторонние настройки и выставь права `600`:

```dotenv
TELEGRAM_BOT_TOKEN=<BOT_TOKEN>
TELEGRAM_ALLOWED_USERS=<TELEGRAM_USER_ID>
TELEGRAM_HOME_CHANNEL=<TELEGRAM_USER_ID>
GATEWAY_ALLOW_ALL_USERS=false
```

Проверь, что `TELEGRAM_USER_ID` — только цифры. Не печатай токен в логах, отчете или диагностических командах. Проверку `getMe` выполняй так, чтобы URL с токеном не попал в пользовательский вывод; сообщи только `ok` и username бота.

До установки gateway проверь импорт Telegram-адаптера из того Python/venv, которым будет запущен сервис. Если журнал сообщает `Platform 'Telegram' requirements not met`, сначала используй поддерживаемый текущим CLI путь настройки (`hermes setup gateway`). Если он не устанавливает зависимость для уже заполненного `.env`, прочитай актуальную запись `platform.telegram` в `tools/lazy_deps.py` или messaging extra в установленном `pyproject.toml` и установи именно объявленную текущей версией зависимость в managed venv. Не закрепляй номер пакета в скилле. После установки снова проверь импорт и перезапусти gateway.

## 6. Gateway 24/7

Для VPS предпочитай системный unit, запускающийся от `hermes`. Команду установки выполняй от root, но укажи home и runtime-пользователя:

```bash
HERMES_HOME=/home/hermes/.hermes hermes gateway install --system --run-as-user hermes --start-now
HERMES_HOME=/home/hermes/.hermes hermes gateway status --system --deep
```

Не угадывай имя systemd-юнита: Hermes может использовать суффикс для профиля или нестандартного home. Найди фактический unit через `hermes gateway status --system` или `systemctl list-unit-files 'hermes-gateway*'` и используй его в проверках журналов.

Подтверди:

- сервис `active (running)` и включен на загрузке;
- в журнале нет циклического рестарта и ошибок OAuth;
- Telegram adapter подключен;
- процесс работает от выбранного runtime-пользователя;
- после рестарта сервиса модель снова отвечает без повторного логина.

Затем попроси пользователя отправить боту `/start` и обычный текстовый вопрос. Голос, веб-поиск, изображения и другие дополнительные инструменты не обещай: у них могут быть отдельные провайдеры и требования.

## 7. SSH-хардненинг

После успешной проверки бота прочитай [references/hardening.md](references/hardening.md) и выполни порядок без перестановок. Telegram polling и OAuth используют исходящие соединения, поэтому входящие порты кроме SSH обычно не нужны.

## 8. Финальная проверка и отчет

Проверь:

- одноразовый запрос к модели;
- сообщение в Telegram;
- allowlist и `GATEWAY_ALLOW_ALL_USERS=false`;
- повторный старт gateway;
- автозапуск;
- владельца процесса и права `600` на секретные файлы;
- вход по SSH-ключу после хардненинга;
- UFW и fail2ban.

Отчет должен содержать: IP/hostname без паролей, runtime-пользователя, подтверждение ChatGPT/Codex OAuth, фактически настроенный slug модели и reasoning effort, username бота, фактическое имя сервиса, пути к конфигурации и OAuth-хранилищу, статус SSH/UFW/fail2ban и список непроверенных дополнительных возможностей.

Если что-то не прошло, не называй раскатку завершенной. Для диагностики прочитай [references/troubleshooting.md](references/troubleshooting.md).
