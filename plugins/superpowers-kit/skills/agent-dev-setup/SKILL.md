# Подготовка окружения для Codex и Claude Code

Этот скилл подготавливает окружение **вокруг** уже установленного Codex или
Claude Code. Он одинаково применим к одному агенту или обоим, но не
устанавливает, не обновляет и не авторизует сами агенты.

## Сначала определи контекст

1. Определи ОС. Поддерживай macOS и нативную Windows; для Linux объясни, что
   готового сценария в этом скилле нет.
2. Выясни, для какого агента нужна настройка: Codex, Claude Code или оба. Если
   пользователь не уточнил, проверь наличие обоих без изменений:
   `codex --version` и `claude --version`.
3. Не считай отсутствие команды ошибкой установки окружения. Сообщи отдельно:
   «Codex/Claude Code не найден; этот скилл не устанавливает агент». Продолжай
   с инструментами, которые пользователь хочет подготовить.
4. Для Claude Code на Windows проверь, что работа идёт через поддерживаемую
   среду (WSL или Git Bash). Если среды нет, сначала предложи установить Git;
   не настраивай WSL и не устанавливай Claude Code без явной отдельной просьбы.

## Принцип работы

- Сначала покажи полный статус основного и расширенного наборов, затем объясни
  только отсутствующие компоненты простыми словами.
- Базовый набор: Homebrew/winget, Git, Node.js и npm, Python, uv, ripgrep,
  jq и curl. Расширенный: Docker, GitHub CLI, pnpm, Yarn, Bun, FFmpeg, Go и
  Deno.
- Не устанавливай всё подряд. Перед **каждой** установкой назови компонент,
  цель и точную команду, затем получи согласие пользователя.
- Инструменты обычно общие для Codex и Claude Code: не дублируй установку, если
  они уже готовы для одного из агентов.
- Не используй `sudo` без необходимости, не обходи системные запросы и не
  проси пароль, API-ключ или токен в чат.
- Не меняй настройки Codex, Claude Code, GitHub, `.env`, проектные файлы или
  глобальные разрешения агентов в рамках этого скилла.

## Сценарий на macOS

Работай из папки этого скилла через `scripts/setup-macos.sh`:

```bash
bash scripts/setup-macos.sh list
bash scripts/setup-macos.sh summary
bash scripts/setup-macos.sh check <id>
bash scripts/setup-macos.sh install <id>
```

Если Homebrew отсутствует, его установка требует отдельного согласия. После
каждой установки повтори `check <id>`. Код `30` означает, что человеку нужно
закончить системный шаг или открыть новый терминал; не выдавай это за успех.

## Сценарий на Windows

Работай из PowerShell через `scripts/setup-windows.ps1`:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-windows.ps1 list
powershell -ExecutionPolicy Bypass -File scripts/setup-windows.ps1 summary
powershell -ExecutionPolicy Bypass -File scripts/setup-windows.ps1 check <id>
powershell -ExecutionPolicy Bypass -File scripts/setup-windows.ps1 install <id>
```

Если отсутствует `winget`, не ищи обходной установщик: объясни, что нужно
обновить App Installer, и остановись на этом компоненте. Не запускай Windows-
сценарий внутри WSL.

## Завершение

Запусти `summary` и дай две отдельные строки: статус окружения и статус
выбранных агентов. Не говори, что агент готов к работе, если его команда не
найдена или у базового компонента остался незакрытый шаг.
