# Полное подключение Obsidian vault

## Цель

За один диалог создать локальный Obsidian vault, подключить его к новому приватному GitHub-репозиторию, записать единые правила для Codex и Claude Code и проверить базовую работу. Пользователь не должен знать Git-команды.

## Единственный стартовый вопрос

Сначала спроси только путь к vault и имя репозитория, предложив значения по умолчанию:

- vault: `~/Documents/Знания`;
- репозиторий: `obsidian-knowledge-base`.

Если пользователь согласен с предложением, не задавай дополнительные плановые вопросы. Определи ОС и доступные инструменты самостоятельно.

## Маршрут

1. Проверь, что путь не находится в iCloud Drive, Dropbox, Google Drive или другой активно синхронизируемой папке. Если находится — объясни конфликт двух синхронизаций и попроси выбрать обычную локальную папку.
2. Сообщи, что создашь vault. Создай корневую папку и только `Входящие/`, `Заметки/`, `Гайды/`. Не создавай искусственную структуру, теги или шаблоны.
3. Проверь Git. Если его нет, объясни, что он хранит историю и синхронизирует файлы, затем запусти штатную для ОС установку. Остановись лишь для системного диалога или действий, которые пользователь должен подтвердить сам.
4. Проверь GitHub CLI (`gh`). Если он отсутствует, установи его штатным способом для ОС или объясни краткий ручной шаг, если система требует его. Проверь авторизацию. При необходимости запусти `gh auth login` и дождись, пока пользователь завершит браузерный вход.
5. До инициализации Git создай `.gitignore` из [setup.md](setup.md). Не игнорируй всю `.obsidian/`.
6. Сообщи, что инициализируешь локальный Git. Проверь список файлов перед первым коммитом. Не добавляй секреты, неожиданные бинарные файлы или содержимое облачных папок.
7. Создай новый приватный GitHub-репозиторий с согласованным именем, сделай первый коммит и отправь vault. Покажи адрес репозитория и проверь, что `.obsidian/workspace.json` не отслеживается.
8. Прочитай [vault-policy.md](vault-policy.md). Покажи краткое резюме общих правил и создай одинаковые `AGENTS.md` и `CLAUDE.md`. Если такие файлы существуют, не заменяй их: покажи различия и запроси решение.
9. Попроси пользователя открыть созданную папку в Obsidian через **Open folder as vault**. Это единственный обязательный ручной шаг в самом Obsidian.
10. Объясни, как в Obsidian установить плагин **Git** от `vinzent03`: Community plugins → Browse → Git → Install → Enable. Попроси включить `Pull on startup` и авто-коммит раз в 5–10 минут. Не называй это мгновенной синхронизацией.
11. Проведи финальную проверку: создай тестовую заметку только во `Входящие/`, прочитай её, покажи Git-статус и объясни, когда она появится на GitHub. Не отправляй тестовый файл в репозиторий без согласования, если авто-коммит ещё не настроен.

## Условия успеха

- Vault находится в локальной папке и открыт в Obsidian.
- Есть `Входящие/`, `Заметки/`, `Гайды/`.
- Git и приватный GitHub-репозиторий подключены.
- `.gitignore` создан до первого коммита и не исключает всю `.obsidian/`.
- `AGENTS.md` и `CLAUDE.md` существуют и совпадают.
- Агент умеет читать vault и без явной просьбы создаёт новое только во `Входящие/`.

## Не делай

- Не требуй MCP для базовой работы с vault.
- Не проси пользователя выполнять Git-команды, если агент может выполнить их сам.
- Не создавай публичный репозиторий.
- Не переноси, не переименовывай и не удаляй заметки.
- Не продолжай после ошибки авторизации GitHub, скрывая проблему: объясни, на каком шаге остановились и как её завершить.
