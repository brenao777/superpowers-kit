# Telegram через Telethon

Цель — создать локальную Telethon-сессию, которую агент сможет использовать только из выбранной пользователем папки. По умолчанию подключение и проверка read-only: не отправляй сообщения, не меняй чаты и не экспортируй сессию.

Скилл одинаково работает из Codex и Claude Code. Он не даёт Telegram-доступа сам по себе: доступ появляется только после локального входа владельца аккаунта.

## Границы и секреты

- Никогда не проси прислать в чат `api_hash`, код входа, пароль 2FA, файл `*.session` или строковую сессию. Пользователь вводит их только в своём терминале.
- `api_id` и `api_hash` — реквизиты приложения Telegram, а не номер телефона. Допустимо использовать пару, созданную в другом личном аккаунте пользователя; не принимай чужие или купленные ключи.
- Не создавай `StringSession`, не печатай сессию и не клади сессию в `.env`, Git, облако, MCP-конфиг или архив.
- Не удаляй, не завершай и не перевыпускай существующую сессию без явного запроса. Если пользователь подозревает утечку, объясни, как завершить её в Telegram → Settings → Devices.
- До любого действия, которое может отправить сообщение, создать чат или изменить данные Telegram, покажи план и дождись явного подтверждения. Этот скилл такого действия не выполняет.

## Последовательность

1. Прочитай [сценарий подключения](references/authentication.md). Уточни путь к новому локальному проекту; по умолчанию предложи `~/telegram-telethon` (или домашнюю папку пользователя на Windows). Не создавай папку без согласия.
2. Убедись, что у пользователя уже есть `api_id` и `api_hash`. Не запрашивай их значения. Если их нет, направь на `my.telegram.org` → **API development tools**; при ошибке регистрации прочитай [диагностику](references/troubleshooting.md).
3. После согласия создай изолированный проект через приложенный bootstrap:

   ```sh
   python3 <путь-к-этому-скиллу>/scripts/bootstrap_project.py --target "<выбранный-путь>"
   ```

   Не добавляй `--force`: bootstrap намеренно отказывается перезаписывать непустую папку.
4. Покажи, какие файлы будут созданы. Затем попроси пользователя самостоятельно скопировать `.env.example` в `.env`, заполнить только `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` и сохранить файл. Не открывай заполненный `.env` и не проси его содержимое.
5. Установи зависимости в `.venv` выбранного проекта с разрешения пользователя. На macOS/Linux используй `python3 -m venv .venv`, Windows — `py -m venv .venv`; затем `pip install -r requirements.txt`. Не ставь пакеты глобально.
6. Предложи QR-вход первым, если пользователь уже вошёл в Telegram на телефоне или Desktop. Запусти `python scripts/qr_login.py`; пользователь сканирует QR через Telegram → Settings → Devices → Link Desktop Device. Если QR истёк, скрипт создаёт новый при следующем запуске.
7. Если QR недоступен, запусти `python scripts/code_login.py`. Номер, код и пароль 2FA вводятся только в локальном терминале. Скрипт сообщает только тип доставки кода; Telegram может прислать его в официальный клиент, по SMS или предложить иной доступный ему вариант.
8. После успешного входа запусти `python scripts/check_readonly.py`. Это подтверждает сессию и не выводит номер телефона, ID или диалоги. Показывать до пяти названий диалогов можно лишь с отдельным флагом `--dialogs` и с согласия пользователя.
9. Сообщи только итог: создана ли локальная сессия и её путь. Напомни, что `telegram.session` и `.env` не должны покидать компьютер.

## Ошибки и следующий слой

- Если скрипт сообщает о 2FA, попроси ввести пароль в терминале через скрытый ввод; не переключайся на менее безопасный способ.
- Если Telegram ограничил повторные входы или регистрации, не зацикливай попытки: остановись, сообщи точный класс ошибки без секретов и предложи повторить позднее.
- Если требуется подключить агента к данным Telegram, сначала проектируй узкий локальный CLI с read-only командами (например, поиск или чтение конкретного чата). MCP добавляй только после отдельного аудита инструментов и явного решения пользователя.
- Для деталей веток входа и восстановления читай [сценарий подключения](references/authentication.md); для проблем с ключами — [диагностику](references/troubleshooting.md).
