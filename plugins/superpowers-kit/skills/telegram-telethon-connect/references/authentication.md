# Сценарий авторизации Telethon

## Что нужно заранее

- Личный Telegram-аккаунт, в который пользователь имеет право входить.
- Свои `api_id` и `api_hash` из `my.telegram.org` → **API development tools**. Telethon указывает, что это реквизиты приложения и их можно использовать с другим номером телефона или бот-аккаунтом. `api_hash` нельзя отозвать, поэтому он остаётся секретом.
- Python 3.10+ и обычный локальный терминал.

`telegram.session` — SQLite-файл с ключом авторизации и частью локального кэша сущностей. Это секрет уровня активной сессии: не копировать, не коммитить и не загружать в облако.

## Вариант A — QR (предпочтительный)

1. После согласия агент запускает `python scripts/open_env_macos.py`: этот лаунчер создаёт `.env` из `.env.example` только если файла ещё нет, выставляет права `600` и открывает `nano` в видимом Terminal. Пользователь вводит два значения сам; агент не читает файл.
2. Скрипт входа сам прочитает из локального `.env` только `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`.
3. Процесс должен выполняться в видимом пользовательском терминале, чтобы скрытый ввод 2FA действительно принадлежал пользователю. На macOS агент запускает `python scripts/launch_qr_login_macos.py`: лаунчер открывает Terminal с `qr_login.py` и повторно выводит его на передний план при запросе 2FA. На других системах пользователь сам запускает `python scripts/qr_login.py` в своём терминале.
4. Агент должен сразу показать созданный `tg_login_qr.png` прямо в сообщении как Markdown-изображение с абсолютным локальным путём. Пользователь сканирует его в официальном Telegram: **Settings → Devices → Link Desktop Device**. Вывод изображения через инструмент может сворачиваться в Codex, поэтому он не заменяет обычное Markdown-изображение в сообщении.
5. Если включена облачная 2FA, macOS-лаунчер автоматически вернёт Terminal на передний план. Ввести пароль в строке `Telegram 2FA password (local input):`; символы не отображаются. Обычная shell-строка с приглашением вроде `%` или `$` не является запросом 2FA. Код или пароль не передаются агенту.
6. Скрипт завершается только после создания локальной `telegram.session`.

QR обычно живёт около 30 секунд. Сначала пользователь открывает экран сканирования, затем агент запускает скрипт и немедленно показывает картинку. Таймаут или истёкший QR не означает ошибку учётной записи: согласовать готовность и запустить скрипт ещё раз для нового кода.

## Проверка ветки 2FA

Если QR-вход завершился без запроса дополнительного пароля, 2FA в этом входе не требовалась; обычно она не включена для аккаунта. Для контролируемой проверки пользователь включает её только в официальном Telegram: **Settings → Privacy and Security → Two-Step Verification**, задаёт уникальный пароль и подтверждает recovery email. Пароль и коды остаются только у пользователя.

Не удалять рабочую `telegram.session` ради проверки. Создать отдельную временную локальную папку через bootstrap, попросить пользователя самостоятельно заполнить её `.env`, затем выполнить QR-вход. После сканирования Telethon должен запросить пароль 2FA через скрытый ввод в интерактивном терминале. Удалять временную сессию или отключать 2FA можно только по явному запросу пользователя.

## Вариант B — вход по коду

Использовать, если нет авторизованного официального клиента для QR или QR не проходит.

1. Запустить `python scripts/code_login.py`.
2. Ввести номер в международном формате в терминале.
3. Telegram сам выбирает доступный канал доставки. Обычно это код в официальном Telegram-клиенте; для некоторых ситуаций может быть SMS или другой предложенный Telegram вариант. Скилл не пытается навязать SMS.
4. Ввести код только в терминале. При включённой 2FA скрипт запросит пароль скрытым вводом.

После лимита, FloodWait или нескольких неудачных попыток остановиться и дождаться времени, указанного Telegram. Не пробовать случайные коды и не создавать новые аккаунты как обход.

## Проверка и отзыв доступа

`python scripts/check_readonly.py` делает только `get_me()` и выводит отображаемое имя без номера и ID. `--dialogs` добавляет чтение пяти названий последних диалогов — это необязательная проверка и требует отдельного согласия.

После подключения агент использует только `scripts/telegram_readonly.py`:

```sh
python scripts/telegram_readonly.py dialogs --limit 10
python scripts/telegram_readonly.py recent --chat "Название чата" --limit 20
python scripts/telegram_readonly.py search --chat "Название чата" --query "дедлайн" --limit 30
```

Команды ничего не отправляют и не редактируют. Но они выводят названия и тексты в локальный контекст агента, поэтому перед каждым таким запуском агент показывает чат, лимит и задачу и ждёт подтверждение пользователя.

При подозрении на утечку: Telegram → **Settings → Devices** → завершить соответствующую сессию, удалить локальный `telegram.session`, затем авторизоваться заново. Утечка `api_hash` требует прекратить использовать пару и обратиться в поддержку Telegram: Telethon предупреждает, что этот секрет нельзя отозвать.
